# ASSERT 执行规范

> 每个 ASSERT 步骤执行时强制遵守，三项均通过才置 pass=true。

---

## 规范0：取证方式优先级（先取证，视觉兜底）

ASSERT 执行第一步**不是截图**，而是判断目标"有没有可取的事实"，按优先级取证：

1. 目标是**元素存在 / 页面进入** → `appium_find_element` 按 id 取证（命中 `elements.truth.json`）→ `verify_method=id`，`confidence=high`
2. 目标是**具体数值 / 文案 / 状态**（昵称、手机号、密码框值、倒计时文案、余额、按钮文案…）→ `appium_get_text` / `get_element_attribute` 取真实值比对 → `verify_method=text`，`confidence=high`
3. **仅当**目标无 id、无可取文本（纯图标 / RN / 短视频流 / 教室画面）→ 才 `appium_screenshot` 视觉判 → `verify_method=vision`，`confidence=low`，报告单独标注待人工复核

> ⚠️ **能 text/id 取证的断言却用视觉肉眼判，等同主动降级可信度，视为不达标。**
> 完整取证链与反幻觉校验（声称的 id 必须存在于 truth.json）见 [locator.md](locator.md)「ASSERT 取证链」。

note 末尾强制追加：`；取证=<id|text|vision>`

---

## 规范1：页面加载完成后再截图

截图前确认页面已稳定，以下任意特征出现则等待消失后再截图：

| 加载中特征 | 判断方式 |
|-----------|---------|
| 骨架屏（灰色占位块） | 截图可见连续灰色矩形块代替真实内容 |
| 转圈 / ProgressBar | 截图可见 spinner 或进度条 |
| "加载中" / "Loading" 文字 | 截图可见相关文字 |
| 列表为空但有请求在途 | page_source 含 loading 相关 resource-id |

等待策略：轮询截图，最多等 5s；超时仍未稳定则 ASSERT FAIL，note 注明"页面未完成加载"。

---

## 规范2：Toast / Snackbar / 提示 需在动作后立即截图

触发 Toast / 提示的 ACTION 执行完毕后，**在 1s 内完成截图**，否则 Toast / 提示消失无法验证。

```
执行 ACTION（如点击"复制"）
↓ 立即（不等待页面跳转）
appium_screenshot maxWidth=800
↓
判断 Toast 文案是否符合预期
```

> 步骤列表中 Toast / 提示类验证点须标注 `[TOAST]`，不可与下一步 ASSERT 合并截图。
> 此类为**软断言**：`[TOAST]` 抢拍拿到证据即 PASS；1s 窗口内没抓到但最终页面状态实证符合预期（如已进入下一页）时不判整条失败，以最终稳定页面状态为准。

---

## 规范3：验证内容"对不对"，不只验证"有没有"

验证点涉及具体数值、文案、状态时，必须核查内容与预期一致，不得仅确认元素存在。

| 场景 | 错误判断 | 正确判断 |
|------|---------|---------|
| 课程名称 | "有课程名称" → PASS | "课程名称为'xxx'" → PASS/FAIL |
| 倒计时/数字 | "有数字显示" → PASS | "显示'重新获取(59)'" → PASS/FAIL |
| 按钮文案 | "有按钮" → PASS | "按钮文案为'获取验证码'且为红色" → PASS/FAIL |
| 列表数量 | "有列表" → PASS | "列表显示 N 条，与预期一致" → PASS/FAIL |

---

## 判断流程

按规范0取证后（无可取 id/text 时才截图），依次回答三个问题：

- **Q1（功能）**：预期内容是否出现？→ func_pass
- **Q2（数据）**：涉及具体数值/文案时，实际内容与预期是否一致？→ data_pass
- **Q3（UI）**：见 [ui_spec.md](ui_spec.md) → ui_pass

**pass = func_pass AND data_pass AND ui_pass**

---

## note 字段（强制填写，不得留空）

```
格式："<实际观测内容>；数据<正常/异常：具体值>；UI<无异常 / 问题：具体描述>；取证=<id|text|vision>"

示例（text 取证）：
"我的页昵称取值'小九'、手机号'123****9000'，与登录账号一致；数据正常；UI无异常；取证=text"

示例（全部通过）：
"获取验证码按钮变为红色可点击；数据正常；UI无异常；取证=id"

示例（UI失败）：
"可见4个验证码输入框；数据正常；UI问题：第4个输入框右边缘被屏幕截断"

示例（数据失败）：
"倒计时显示中；数据异常：显示'重新获取(0)'，预期应为倒计时数字；UI无异常"
```
